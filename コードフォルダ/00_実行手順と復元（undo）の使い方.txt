========================================================================
 ファイル整理ノートブック 実行手順と復元（undo）の使い方
========================================================================
 最終更新: 2026-09-01
 対象: コードフォルダ内の 01〜06 のノートブック（.ipynb）


------------------------------------------------------------------------
 結論：今まで通りのやり方で大丈夫です
------------------------------------------------------------------------

これまでの手順（各セルを上から順に実行し、戻したいときは undo コードを
実行し、終わったら次のノートブックを開いて最初のセルから順に実行する）は
そのまま使えます。

ただし、全ノートブックに復元機構を入れた関係で、変わった点が3つあります。


------------------------------------------------------------------------
 変わった点 その1：最初のセル（import）は必ず実行する
------------------------------------------------------------------------

各ノートブックの [1] 番目のコードセルが、共通の復元基盤である
undo_utils.py を読み込んでいます。

  ★ 復元セルだけを実行したいときも、先に [1] を実行してください。
    飛ばすと「uu が未定義」というエラーになります。

VS Code のカーネルを再起動した直後も同じです。まず [1] から実行します。


------------------------------------------------------------------------
 変わった点 その2：復元セルが全6本の末尾にあり、履歴は共有される
------------------------------------------------------------------------

以前は 01 と 04（Futaba用）にしか復元コードがありませんでした。
今は 01〜06 すべての末尾に、まったく同じ「復元セル」が入っています。

そして、どのノートブックの復元セルを押しても【同じ履歴】を読みます。

  → 「02 で失敗したのに 02 を閉じてしまった」というときも、
    いま開いているノートブックの復元セルでそのまま戻せます。
    わざわざ 02 を開き直す必要はありません。

履歴は、選んだメインフォルダの中の次の場所に記録されています。

    メインフォルダ/
      _undo/undo_log.json   ← 全工程の操作履歴
      _trash/               ← 削除の代わりの退避先


------------------------------------------------------------------------
 変わった点 その3：復元は「1回押すと1工程だけ」戻る
------------------------------------------------------------------------

これが一番大きな違いです。工程を飛び越して戻すことはできません。
たとえば 01 まで戻したいなら、05 → 04 → 03 → 02 → 01 と順に押します。

ただし、押す前に履歴の一覧が表示され、
「← 次に復元されるステップ」がどれかがわかります。
回数を覚える必要はありません。表示を見て、戻したいところまで
繰り返し押してください。

  ＜復元セルを実行したときの表示例＞

    復元ログ: ...\メインフォルダ\_undo\undo_log.json
    ------------------------------------------------------------
     1. 01_サブフォルダ名の変更
        2026-09-01T16:03:12 / 操作 5 件
     2. 02_ファイル分別 (1工程目 仕分け)
        2026-09-01T16:03:12 / 操作 56 件
     3. 02_ファイル分別 (2工程目 空フォルダ削除)
        2026-09-01T16:03:12 / 操作 25 件
     4. 02_ファイル分別 (最終段階 階層の再編成)
        2026-09-01T16:03:12 / 操作 20 件 ← 次に復元されるステップ
    ------------------------------------------------------------

    復元中: 02_ファイル分別 (最終段階 階層の再編成)
      完了: 20 件を復元

    復元が完了しました。


------------------------------------------------------------------------
 ノートブックごとの実行セルと、全部戻すのに押す回数
------------------------------------------------------------------------

 01_サブフォルダ名の変更と復元
     実行するコードセル … [2]
     全部戻すのに       … 1回

 02_ファイル分別
     実行するコードセル … [3] → [5] → [7]
     全部戻すのに       … 3回

 03_複数末端フォルダにおける一斉ファイル数調整
     実行するコードセル … [4]（NR用）か [6]（Futaba用）の どちらか一方
     全部戻すのに       … 1回

 04_分別後のファイル名変更
     実行するコードセル … NR用     は [5] → [7]
                          Futaba用 は [9] → [10]
                          （NR用か Futaba用の どちらか一方だけ）
     全部戻すのに       … 2回

 05_ファイル名の末尾にそのひとつ前のフォルダ名を付け足す
     実行するコードセル … [4]
     全部戻すのに       … 1回

 06_全処理終了後_連番数字の変更
     実行するコードセル … [3]
     全部戻すのに       … 1回

 ※ セル番号は、markdown セルも含めて上から 0 と数えた番号です。
 ※ 変更が0件だった工程は履歴に残らないため、押す回数はこれより
    少なくなることがあります。表示される一覧で確認してください。


------------------------------------------------------------------------
 今まで通りで、変わらない点
------------------------------------------------------------------------

 ・セルを上から順に実行する。

 ・02 の [3] と [5] は続けて実行する。
   （[5] は [3] で決めた main_folder_path を使うため。
     カーネルを再起動した場合は [3] からやり直してください）

 ・03 と 04 は、NR用 か Futaba用 の どちらか一方だけを実行する。
   （両方実行すると二重に処理されてしまいます）

 ・次のノートブックを開いたら、また [1] から順に実行する。


------------------------------------------------------------------------
 注意してほしいこと
------------------------------------------------------------------------

【1】復元セルでは、その工程を実行したときと同じフォルダを選ぶこと

    履歴は「選んだフォルダ」の中の _undo に記録されます。
    別のフォルダを選ぶと「復元用のログが見つかりません」と表示されます。

    特に 06 は下位のフォルダを選ぶことが多いので注意してください。
    06 で メイン/csv/160/subsub を選んだなら、
    復元でも同じ メイン/csv/160/subsub を選ぶ必要があります。

    01〜05 は通常メインフォルダを選ぶので、いつも同じ場所になります。


【2】_trash フォルダは自動では空にならない

    03 で「削除」されたファイルは、実際には削除されず
    メインフォルダ直下の _trash に退避されています。
    （02 の2工程目で見つかった .DS_Store なども同じです）

    問題ないことを確認できたら、_trash フォルダを手動で削除してください。
    復元セルで戻した場合は、_trash は自動的に消えます。


【3】以前の undo_log.json は読めない

    ログの形式を統一したため、改修前のコードが作った
    「メインフォルダ直下の undo_log.json」は新しいコードから読めません。

    途中まで処理を進めているデータフォルダがある場合は、
    先に git で1つ前のコードに戻して復元を済ませてから、
    新しいコードを使ってください。


------------------------------------------------------------------------
 各ノートブックが何をするか（復元できるかどうか）
------------------------------------------------------------------------

 すべての工程が復元できます。処理内容は次の通りです。

 01  メインフォルダ内のサブフォルダ名を、射出速度（160〜320）に変更
 02  拡張子ごとにファイルを仕分け → 空フォルダを削除 → 階層を再編成
 03  末端フォルダ内のファイル数を10件に調整（超過分は _trash へ退避）
 04  ファイル名を「連番_サブサブフォルダ名_サブフォルダ名」に変更し、
     1つ上の階層へ移動、末端フォルダを削除、連番を振り直し
 05  ファイル名の末尾に、ひとつ前のフォルダ名を付け足す
 06  連番のスタート番号を変えて、連番を振り直す


------------------------------------------------------------------------
 undo_utils.py について
------------------------------------------------------------------------

 コードフォルダ内の undo_utils.py が、全ノートブック共通の復元基盤です。

 ★ このファイルは削除・移動しないでください。
   ノートブックと同じ「コードフォルダ」内にある必要があります。

 記録しているのは move（移動・名前変更）、mkdir（フォルダ作成）、
 rmdir（空フォルダ削除）の3種類だけで、復元はそれを逆順に再生します。
 「削除」は _trash への移動として扱っているので、削除も同じ仕組みで
 元に戻せます。
